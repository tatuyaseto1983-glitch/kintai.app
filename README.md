# 勤怠・有給・稟議 管理アプリ

6名ほどの小さなチーム向けに、**打刻・休暇（有給）・休日出勤・稟議（購入申請）** を1つにまとめたWebアプリです。
スマホからもパソコンからも使えます。いま Google スプレッドシート＋フォームで行っている運用を、そのまま置き換えられる項目にしています。

## できること

| | 社員 | 管理者 |
|---|---|---|
| 打刻（出勤・退勤・中抜け後の再開 1日5回まで） | ○ | ○ |
| 自分の勤怠の確認・備考の記入 | ○ | ○ |
| 休暇申請（有給・振替休日・特別休暇など／引継ぎ事項つき） | ○ | ○ |
| 休日出勤申請（振替休日の予定日つき） | ○ | ○ |
| 稟議＝購入申請（品名・数量・経費種別・見積金額・見積書の添付） | ○ | ○ |
| 全員の出勤状況・退勤の打刻漏れの確認 | | ○ |
| 勤怠の修正（時刻・休憩・備考） | | ○ |
| 月次集計（出勤日数・総労働時間・残業時間）とCSV出力 | | ○ |
| 有給の付与・残日数・年5日取得義務の確認 | | ○ |
| 休暇・休日出勤・稟議の承認／差戻し | | ○ |
| 社員の追加・権限変更・利用停止・パスワード再発行 | | ○ |

### 労働時間の計算ルール（今のスプレッドシートと同じ）

- 実働が **6時間を超えた日は休憩60分** を自動で差し引きます
- **8時間を超えた分** を残業として数えます
- 管理者は日ごとに休憩時間を上書きできます（例：休憩なしの日は 0 分）
- 日付をまたいだ勤務（例：22:00〜翌1:00）にも対応しています

ルールは起動時の設定で変えられます（下の「設定」参照）。

## 動かし方

必要なもの：**Node.js 22.5 以上**（追加のインストールは不要です）

```bash
npm start
```

ブラウザで `http://localhost:3000` を開きます。

### 最初にやること

1. 初期の管理者アカウントでログイン（ID：`admin`／パスワード：`admin1234`）
2. 新しいパスワードに変更（初回は必ず変更を求められます）
3. 「社員の管理」→「社員を追加する」で、6名を登録
   - ログインIDはメールアドレスがおすすめです
   - 承認する方（決裁者）は権限を「管理者」にします
   - 入社日を入れておくと、有給の法定日数の目安が表示されます
4. 「休暇・有給の管理」→各社員の「付与・履歴」で、**今の有給残日数**を登録

## 設定（環境変数）

| 名前 | 初期値 | 内容 |
|---|---|---|
| `PORT` | 3000 | 待ち受けるポート番号 |
| `DATA_DIR` | `./data` | データ（データベース・添付ファイル）の保存先 |
| `ADMIN_LOGIN_ID` / `ADMIN_PASSWORD` | admin / admin1234 | 最初に作る管理者（初回起動時のみ） |
| `BREAK_AFTER_MIN` | 360 | この分数を超えて働いたら休憩を差し引く |
| `BREAK_MIN` | 60 | 自動で差し引く休憩の分数 |
| `STANDARD_WORK_MIN` | 480 | これを超えた分を残業とする |
| `SECURE_COOKIE` | （なし） | HTTPS で公開するときは `1` にする |

## 社内で使うための公開について

社員がスマホから使うには、インターネット上のサーバーに置く必要があります。

- **Render / Railway / Fly.io などのサービス**：データを保存する「ディスク（ボリューム）」を付けて、`DATA_DIR` をそこに向けてください。ディスクがないと再起動のたびにデータが消えます
- **小さなレンタルサーバー（VPS）**：`npm start` を常駐させ、HTTPS（Caddy や nginx など）を前に置きます

どちらの場合も、HTTPS で公開し `SECURE_COOKIE=1` を設定してください。

### バックアップ

`data` フォルダ（`kintai.db` と `uploads`）をまるごとコピーすれば、バックアップになります。1日1回のコピーを推奨します。
