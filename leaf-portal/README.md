# 株式会社リーフ 社内ポータル 勤怠管理（GASバックエンド）

Google スプレッドシートをデータベースにして、Google Apps Script（GAS）で勤怠を処理するバックエンドです。
**スタッフ画面（Webアプリ）** も入っています（K を参照）。管理者画面は次の段階で作ります。

> このフォルダは、リポジトリ直下の `gas/`（ID・パスワード方式の別の勤怠アプリ）とは**別物**です。
> 混ぜずに、**新しいスプレッドシート**に入れてください。

---

## A. ファイル一覧（`leaf-portal/gas/`）

| ファイル | 役割 |
|---|---|
| `Config.gs` | シート名・列名・選択肢・設定の初期値（最初に見るファイル） |
| `Utils.gs` | 共通の道具（戻り値の形、日付・時刻の変換、同時実行ロック） |
| `SheetService.gs` | シートの読み書き（見出し名で列を探す／まとめて読み書き） |
| `SettingsService.gs` | 「設定」シートの値を読み込む |
| `Setup.gs` | `setupSystem()`（シート作成）、`addSampleStaff()`（テスト用スタッフ追加）、メニュー |
| `UserService.gs` | `getCurrentUser()`（ログインユーザーの判定）、勤務ルール |
| `AttendanceService.gs` | `clockIn()` `clockOut()` `getMyAttendance()` `getTodayStaffStatus()`、勤務時間の計算 |
| `BreakService.gs` | `startBreak()` `resumeWork()` |
| `OvertimeService.gs` | 事前残業申請、承認・却下、社内超過時間との照合 |
| `FlexService.gs` | `getFlexSummary()`、週1日の完全休日の確認 |
| `CorrectionService.gs` | 打刻修正申請、承認（勤怠へ反映）・却下 |
| `DailyReportService.gs` | 日報の保存・一覧・確認 |
| `AdminService.gs` | `requireAdmin()` と管理者用の機能（日別・月別・承認待ち・CSV・再計算） |
| `TestRunner.gs` | 動作確認用（手動テスト・自動テスト） |
| `WebApp.gs` | スタッフ画面の入口 `doGet()`、画面用の情報取得 `getStaffDashboard()` |
| `Index.html` / `Styles.html` / `Scripts.html` | スタッフ画面の骨組み・見た目・動き |
| `appsscript.json` | タイムゾーン（Asia/Tokyo）などの設定 |

clasp（パソコンから一括反映）用のファイル（`leaf-portal/` 直下。Apps Script には送られません）：

| ファイル | 役割 |
|---|---|
| `package.json` | clasp のバージョン指定と、`npm run push` などの短いコマンド |
| `.clasp.json.example` | 反映先の設定の見本（コピーして `.clasp.json` を作る） |
| `tools/check-clasp.js` | push 前に反映先の設定を確認する（間違っていれば止める） |
| `.gitignore` | `.clasp.json` とログイン情報を Git に入れないための設定 |

関数名の最後に `_` が付いているものは内部用です（画面から呼べず、実行ボタンの一覧にも出ません）。

## B. 最初にやる作業（clasp でパソコンから一括反映）

ファイルを1つずつコピーする代わりに、Google 公式のツール **clasp（クラスプ）** を使って、
パソコンの `leaf-portal/gas` にある19ファイルをまとめて Apps Script に反映します。

### 全体の流れ

```
[1] 新しいスプレッドシートを作る → [2] Apps Script を開いてスクリプトIDをコピー
→ [3] Apps Script API をオン → [4] パソコンの準備（Node.js・ファイル）
→ [5] clasp login → [6] .clasp.json にスクリプトIDを書く → [7] npm run push
→ [8] setupSystem を実行 → [9] runAllScenarioTests を実行
```

> **安全のための約束**
> - 反映先は **この勤怠システム用に新しく作ったスプレッドシートの Apps Script だけ**にしてください。
>   既存の勤怠アプリ（リポジトリの `gas/`）の Apps Script を指定すると、そちらのコードが置き換わって動かなくなります。
> - `clasp push` が置き換えるのは **Apps Script のコードだけ**です。スプレッドシートのデータ（シートの中身）は変わりません。
> - コードの修正は **パソコン側だけ**で行い、`npm run push` で反映します。
>   ブラウザの Apps Script 画面で直接書き換えると、次の push で上書きされて消えます。`clasp pull` は使わないでください。

### B-1. 新しいスプレッドシートを作る

1. ブラウザで Google ドライブを開き、**新規 → Google スプレッドシート → 空白のスプレッドシート**
2. 左上の「無題のスプレッドシート」を「**リーフ 勤怠データ**」などに変更

### B-2. Apps Script を開いて「スクリプトID」をコピーする

1. そのスプレッドシートのメニュー **拡張機能 → Apps Script** を開く（スプレッドシートに紐づいたプロジェクトが作られます）
2. 左上の「無題のプロジェクト」を「**リーフ 勤怠システム**」などに変更
3. 左端の **⚙（プロジェクトの設定）** を開く
4. 「ID」の **スクリプト ID** の横の「コピー」を押す（`1` で始まる50文字以上の英数字）
   - ※「デプロイID（AKfy… で始まる）」や、スプレッドシートのURLの中のIDではありません
5. このタブは開いたままにしておく

### B-3. Apps Script API をオンにする（最初の1回だけ）

1. ブラウザで **https://script.google.com/home/usersettings** を開く
   （スプレッドシートと同じ Google アカウントでログインしていること）
2. 「**Google Apps Script API**」を **オン** にする
3. オンにしてから反映まで数分かかることがあります

### B-4. パソコンの準備

1. **Node.js をインストール**：https://nodejs.org/ja から「**LTS（推奨版）**」をダウンロードしてインストール（20 以上が必要）
2. **コマンドを打つ画面を開く**
   - Windows：スタートメニューで「**コマンドプロンプト**」を開く（PowerShell より問題が起きにくいです）
   - Mac：「アプリケーション → ユーティリティ → **ターミナル**」
3. Node.js が入ったか確認（`v20` 以上の数字が出れば OK）
   ```
   node -v
   ```
4. **このリポジトリのファイルをパソコンに置く**
   - GitHub でリポジトリを開き、ブランチを `claude/festive-cori-wqhu6m` に切り替え →
     緑の **Code → Download ZIP** → ダウンロードした ZIP を右クリックで「すべて展開」
   - （git を使える方は `git clone` でも構いません）
5. **leaf-portal フォルダに移動**：`cd ` と入力（cd の後ろに半角スペース）してから、
   展開したフォルダの中の **leaf-portal フォルダを画面にドラッグ＆ドロップ** → Enter
   ```
   cd （leaf-portal フォルダの場所）
   ```
6. clasp をインストール（このフォルダの中だけに入ります。1〜2分）
   ```
   npm install
   ```

### B-5. clasp にログインする（最初の1回だけ）

```
npm run login
```

1. ブラウザが開くので、**スプレッドシートを作ったのと同じ Google アカウント**を選ぶ
2. 「Google hasn't verified this app」などが出たら内容を確認して続行し、権限の一覧は **すべて許可**（「すべて選択」があれば選ぶ）
3. ブラウザに「Logged in! You may close this page.」と出たら成功。コマンド画面に戻る
4. 確認：`npm run whoami` で自分のメールアドレスが出れば OK

ログイン情報はパソコンのユーザーフォルダの `.clasprc.json` に保存されます（このフォルダには入りません。人に渡さないでください）。

### B-6. `.clasp.json`（反映先の設定）を作る

`.clasp.json` は「どの Apps Script に反映するか」を書く小さなファイルです。見本の `.clasp.json.example` をコピーして作ります。

Windows（コマンドプロンプト）：
```
copy .clasp.json.example .clasp.json
notepad .clasp.json
```
Mac（ターミナル）：
```
cp .clasp.json.example .clasp.json
open -e .clasp.json
```

開いたファイルの `ここにスクリプトIDを貼り付け` を、B-2 でコピーしたスクリプトIDに置き換えて保存します。

```json
{
  "scriptId": "1AbC...（B-2 でコピーしたID）...xyz",
  "rootDir": "gas"
}
```

- `"rootDir": "gas"` は「leaf-portal/gas の中のファイルだけを反映する」という意味です。変えないでください。
- `.clasp.json` は人・環境ごとに違うため、Git には保存されません（`.gitignore` 済み）。

設定の確認（反映はしません）：
```
npm run check
```
`✔ 反映先のスクリプトID：…` と `✔ 反映するファイル（19個）` が出れば OK。
表示されたIDが、Apps Script の ⚙ に出ている「スクリプト ID」と同じか見比べてください。

### B-7. 全ファイルを反映する（`clasp push`）

```
npm run push
```

- 最初に自動で設定を確認し、問題があれば ✖ を表示して **反映せずに止まります**
- 「Manifest file has been updated. Do you want to push and overwrite?」と聞かれたら `y` → Enter
  （`appsscript.json`＝日本時間などの設定を反映してよいか、という確認です）
- `Pushed 19 files at （時刻）.` と出れば成功
- Apps Script のタブを **再読み込み** すると、左に `Config.gs` など19ファイルが並びます
  （最初からあった `コード.gs` は、パソコン側にないので消えます。これで正常です）

コードを直したときも、同じく `npm run push` だけで反映できます。

### B-8. `setupSystem()` を実行する（シートの作成）

1. Apps Script の画面で、左の一覧から **`Setup.gs`** をクリック
   （上の「実行する関数」の一覧には、**開いているファイルの関数**が出ます）
2. 上の一覧から **`setupSystem`** を選び、**▷ 実行**
3. 初回は「承認が必要です」→ **権限を確認** → ご自身のアカウント →
   「このアプリは Google で確認されていません」→ **詳細** → **（プロジェクト名）（安全ではないページ）に移動** → **許可**
4. 下の「実行ログ」に **【セットアップ結果】** と7シートの結果が出れば成功
5. スプレッドシートのタブに戻り、7つのシートができているか確認
   `スタッフマスタ / 勤怠記録 / 中断履歴 / 打刻修正申請 / 残業申請 / 日報 / 設定`
6. スプレッドシートを再読み込みすると、上のメニューに **「勤怠システム」** が出ます

- `setupSystem()` は **何回実行しても安全**です。既存のシート・データ・設定値は消しません。
  足りないシート、足りない見出し（右端に追加）、足りない設定項目だけを追加します。
- 最初からある「シート1」は削除しません。不要なら手で削除してください。

### B-9. `runAllScenarioTests()` を実行する（実機での自動テスト）

1. 左の一覧から **`TestRunner.gs`** をクリック
2. 上の一覧から **`runAllScenarioTests`** を選び、**▷ 実行**（1〜3分かかります）
3. 実行ログの最後に **「◯件中◯件 成功（すべて成功）」** と出れば OK
4. マイドライブに「**Leaf勤怠_自動テスト用（削除してOK）**」というファイルができます。
   テストはこの別ファイルの中だけで行うので、**本番のスプレッドシートには書き込みません**

あわせて **`testLoginCheck`**（同じ `TestRunner.gs`）を実行すると、
あなたのメールアドレスが取得できているか・スタッフマスタに登録されているかを確認できます（データは変えません）。

### （予備）clasp を使えないとき

Apps Script 画面の左の **＋ → スクリプト** でファイルを作り、`leaf-portal/gas` の各 `.gs` の中身を貼り付けても動きます
（ファイル名は `.gs` を除いた名前。作る順番は自由）。`appsscript.json` は ⚙ で「"appsscript.json" マニフェスト ファイルをエディタで表示する」をオンにすると編集できます。

## C. テスト方法

### C-1. まず自動テスト（おすすめ・3分）

1〜12 の確認を、**本物のシートを使わずに**まとめて行います。

1. Apps Script で **`runAllScenarioTests`** を選んで ▷ 実行（初回は権限の許可が再度出ることがあります）
2. 実行ログに ✅／❌ が並び、最後に **「◯件中◯件 成功（すべて成功）」** と出れば OK

   中を開くと、テストで作られた勤怠記録・残業申請などを実際に見られます（2回目以降は同じファイルを使い回します）

## E. 画面から呼ぶ関数（`google.script.run` で呼びます。スタッフ画面で使っているものは K-1）

戻り値はすべて同じ形です。

```js
{ success: true,  message: '出勤しました（出社・09:30）', data: { ... } }
{ success: false, message: '本日はすでに出勤済みです（出勤 09:30）', data: null }
```

| 関数 | 誰が | data の中身 |
|---|---|---|
| `getCurrentUser()` | 全員 | employeeId, name, email, role, isAdmin, workType, department |
| `clockIn('出社' または '在宅')` | 全員 | 勤怠1件（下の「勤怠の項目」） |
| `startBreak(理由)` / `resumeWork()` / `clockOut()` | 全員 | 勤怠1件 |
| `getMyAttendance('2026-09')` | 全員（本人分のみ） | month, from, to, records[], totals |
| `getTodayStaffStatus()` | 全員 | date, staff[{ name, workStyle, status, label, isSelf }]（isSelf＝自分の行なら true。**時間・遅刻・残業は返さない**） |
| `getFlexSummary(社員ID)` | フレックス本人／管理者 | week・month の scheduled, worked, remaining, excess、week.restDayCheck |
| `submitOvertimeRequest({ targetDate, plannedStart, plannedEnd, reason })` | 全員 | 申請1件 |
| `submitCorrectionRequest({ targetDate, item, before, after, reason })` | 全員 | 申請1件 |
| `getMyOvertimeRequests()` / `getMyCorrectionRequests()` | 全員 | 申請の一覧 |
| `saveDailyReport({ date, workContent, progress, issues, tomorrowPlan, sharedNotes, status })` | 全員 | 日報1件 |
| `getMyDailyReports('2026-09')` | 全員 | month, reports[] |
| `approveOvertimeRequest(id)` / `rejectOvertimeRequest(id, 理由)` | 管理者 | 申請1件 |
| `approveCorrectionRequest(id)` / `rejectCorrectionRequest(id, 理由)` | 管理者 | 申請1件（承認で勤怠へ反映・再計算） |
| `confirmDailyReport(id)` | 管理者 | 日報1件 |

## F. 【重要】ログインユーザー判定：Google Workspace 運用と個人 Gmail 運用の違い

このシステムは `Session.getActiveUser().getEmail()`（操作している人のメールアドレス）でスタッフを判定します。
**このメールアドレスが取れるかどうかは、アカウントの種類と Webアプリの公開設定で変わります。**

### いつ取れるか

| 使い方 | Google Workspace 運用（全員が @会社ドメイン） | 個人 Gmail 運用（全員が @gmail.com など） |
|---|---|---|
| Apps Script 画面から実行（今回のテスト） | 取れる | 取れる |
| スプレッドシートのメニューから実行 | 取れる | 取れる（その人に編集権限がある場合） |
| Webアプリ：「自分」として実行 | **取れる**（所有者と利用者が同じドメインの場合） | **取れない（空になる）** ※所有者本人だけは取れる |
| Webアプリ：「アクセスしているユーザー」として実行 | 取れる | 取れる。ただし全員にスプレッドシートの編集権限が必要 |

### 取れないときの動き（コードで保証していること）

- メールアドレスが空・取得時にエラー・形式がおかしい場合は、**必ずエラーで止まり、打刻などは一切記録しません**。
  画面には「Googleアカウントのメールアドレスを取得できませんでした。打刻などの処理は行っていません。…」と返します。
- `Session.getEffectiveUser()`（＝スクリプトを実行している権限の持ち主。「自分として実行」なら所有者）で
  **代用することはしません**。代用すると、全員が所有者として打刻される誤動作になるためです。
- 確認用に `testLoginCheck`（TestRunner.gs）を用意しています。取得できたアドレスと、スタッフマスタでの判定結果をログに出します。

### どちらで運用するか（画面を作る前に決める）

| | 内容 | 良い点 | 注意点 |
|---|---|---|---|
| **第一候補** | Google Workspace（会社ドメイン）で運用。Webアプリは「自分として実行」＋「アクセス：組織内のユーザー」 | 今のコードのまま使える。社外の人は開けない。スタッフにシートの権限を渡さなくてよい | Workspace の契約（有料）が必要 |
| 第二候補 | 個人 Gmail のまま。画面側で Google ログイン（Google Identity Services）を行い、GAS 側でログイン情報を検証してメールアドレスを確認する方式に変更 | 追加費用なし | 画面・GAS の追加開発が必要（次の段階で対応可） |
| おすすめしない | 個人 Gmail で「アクセスしているユーザーとして実行」＋全員にシートの編集権限 | すぐ動く | スタッフがシートを直接書き換えられ、「申請→承認」の仕組みが意味をなくす |

## G. データの保存形式と、シートを直接直すときの注意

- 日付・時刻・時間は **文字列（書式なしテキスト）** で保存しています（例：`2026-09-29`、`09:30`、`08:10`、`138:00`）。
  「09:30」が勝手に別の値に変わるのを防ぐためです。手で入力するときも同じ形で入力してください。
- 列は **見出し名** で探しているので、列の並べ替えや右側への独自の列の追加をしても動きます。**見出し名は変えないでください**。
- シート上で出勤・退勤・中断履歴・残業申請のステータスを直接直したら、
  メニュー **勤怠システム → 今月の勤怠を再計算（管理者）** で計算列（実働・社内超過・要確認など）を更新してください。
- 勤怠記録・申請の行は削除しないでください（修正は打刻修正申請で）。

## H. 勤怠ルール（実装内容）

- **実働時間** ＝ 退勤 − 出勤 − 自動休憩（1:00）− 中断合計（マイナスにはしない）
- **固定勤務**：09:30 より後の出勤は「遅刻」、18:30 より前の退勤は「早退」、18:30 以降は「社内超過時間」（1分単位）
  - 社内超過時間は**社内管理用の数字**で、法律上の時間外労働（1日8時間・週40時間超）の計算とは別です
  - 30分以上なら承認済みの事前残業申請が必要。なければ「要確認」。**打刻・実働は申請に合わせて削ったり丸めたりしません**
- **フレックス**：遅刻・早退・社内超過は判定しません。週 32:00・月 138:00 に対する実働・残り・超過を集計
- **週1日の完全休日**：出勤記録がない日を完全休日として数え、`getFlexSummary()`（本人）と `checkWeeklyRestDays()`（管理者・全員）で確認
- **日付をまたぐ勤務**（例：22:00〜翌1:00）：前日の記録に退勤できます
- **同時実行**：出勤・退勤・中断・再開・申請・承認は LockService で1件ずつ順番に処理

### 設定シートの項目

指示いただいた10項目に加えて、次の3項目を追加しています（初期値は指示どおりの動きになる値です）。

| 項目 | 初期値 | 意味 |
|---|---|---|
| 週_起算曜日 | 月 | 週の集計を何曜日から始めるか |
| 月_締め日 | 末日 | 「末日」または 1〜27（例：20＝21日〜翌月20日） |
| 自動休憩_適用開始 | 00:00 | 中断を除いた勤務時間（退勤−出勤−中断合計）がこの時間を**超えた**日だけ自動休憩を引く（00:00＝常に引く） |

**短時間勤務で自動休憩を引かないようにするには**：「設定」シートの `自動休憩_適用開始` の値を `06:00` に変えるだけです（コードの修正は不要）。
次の退勤から、中断を除いて6時間ちょうどまでの日は自動休憩 00:00、6時間を超えた日は 01:00 になります。
すでに記録済みの日も直したいときは、メニュー「今月の勤怠を再計算（管理者）」を実行してください。
何時間にするか（例：法律上は6時間超で45分・8時間超で1時間の休憩が必要）は、社労士に確認のうえ決めてください。

## K. スタッフ画面（Webアプリ）

ブラウザ（PC・スマホ）から、出勤・中断・再開・退勤、今日の記録、今月の勤怠、フレックス累計、全スタッフの状況、
打刻修正申請、日報の入力ができます。**管理者画面はまだありません**（次の段階で作ります）。

### K-1. 画面のファイル

| `WebApp.gs` | `doGet()`（URLを開いたときに画面を返す）と、画面の表示に必要な情報をまとめて返す `getStaffDashboard()`（読み取りのみ） |
| `Index.html` | 画面の骨組み（ヘッダー・カード・フォーム） |
| `Styles.html` | 見た目（色・レイアウト・スマホ対応）。色は先頭の `:root` にまとめています |

画面から呼んでいるサーバーの関数（`Scripts.html` の `ALLOWED_FUNCTIONS` 以外は呼びません）：

| 関数 | 使う場面 |
|---|---|
| `getStaffDashboard(parts)` ※新規 | 初回表示・打刻後の更新（中で既存の `getCurrentUser` `getMyAttendance` `getTodayStaffStatus` `getFlexSummary` を呼ぶ） |

| `saveDailyReport(report)` / `getMyDailyReports(month)` | 日報の保存（下書き／提出）・読み込み |

- 画面から**社員IDは一度も送りません**。本人は必ずサーバー側でログイン中のGoogleアカウントから判定します。
- `getFlexSummary()` も社員IDなし（＝本人の集計）で呼びます。管理者用の関数は呼びません。

### K-2. 既存のバックエンドへの変更（理由と内容）

既存の関数の動き・既存の戻り値の項目は変えていません。変更は次の2点です。

- **`setupSystem()` `addSampleStaff()` `runAllScenarioTests()` の先頭に、「エディタ・メニューから本人として実行されているか」の確認を追加**（`Setup.gs` の `requireEditorExecution_`）
  - 理由：Webアプリとして公開すると、Apps Script の仕組み上、名前の最後に `_` が付いていない関数は、スタッフがブラウザの開発者ツールから呼び出せてしまいます。
    「自分として実行」で公開すると、これらが**所有者の権限で**動き、テスト用スタッフが本番シートに追加されたり、所有者のドライブにテスト用ファイルが作られたりするおそれがあるためです。
  - 動き：Webアプリ経由（操作している人 ≠ 所有者）のときは「Webアプリからは実行できません」で止まります。
    エディタから実行する場合は今までどおり動きます（自動テスト 43件もそのまま成功します）。
- **`getTodayStaffStatus()` の各行に `isSelf`（自分の行なら true）を追加**（`AttendanceService.gs`）
  - 理由：全スタッフ一覧の「（あなた）」を氏名で判定すると、同姓同名のときに2人とも「あなた」になるため。サーバー側で社員IDを比べて判定します
  - 既存の項目（name, workStyle, status, label）は変えていません。社員IDやメールアドレスは返しません
- 追加（変更ではない）：`WebApp.gs` の `doGet()` と `getStaffDashboard()`。

### K-4. まず自分だけで確認する（テストデプロイ）

公開前に、自分だけが開けるURLで動作を確認できます。

1. パソコンで `npm run push`（B-7 と同じ）→ 19ファイルが反映される
2. Apps Script の画面右上の **デプロイ → デプロイをテスト**
3. 「種類の選択」の歯車 ⚙ で **ウェブアプリ** が選ばれていることを確認
4. 表示された **ウェブアプリの URL（末尾が `/dev`）** をクリック
5. 初回は権限の確認が出るので許可する → スタッフ画面が表示されます

- `/dev` のURLは、**保存・push した最新のコードがすぐ反映**されます（開けるのはプロジェクトの編集権限がある人だけ）。
- 自分のメールアドレスがスタッフマスタに登録されている必要があります（D の手順）。
- 打刻は**本物のシートに記録**されます。テストした記録が不要なら、管理者が勤怠記録・中断履歴の該当行を削除してください（テスト期間中のみ）。

### K-5. スタッフに公開する（新しいデプロイ）

会社の Google Workspace アカウントでの運用を前提にしています（理由は F）。

1. Apps Script を開く（スプレッドシートの **拡張機能 → Apps Script**、またはパソコンで `npm run open`）
2. 右上の **デプロイ** を押す
3. **新しいデプロイ** を選ぶ
4. 「種類の選択」の歯車 ⚙ → **ウェブアプリ**
5. 説明：例「スタッフ画面 v1」
6. **次のユーザーとして実行**：**自分（あなたのメールアドレス）** を選ぶ
   - スタッフはスプレッドシートの権限がなくても、この画面からだけ打刻できます
   - 「ウェブアプリにアクセスしているユーザー」を選ぶと、スタッフ全員にシートの編集権限が必要になり、シートを直接書き換えられてしまうので**選ばないでください**
7. **アクセスできるユーザー**：**「（会社名）内の全員」**（Workspace のドメイン名が表示される項目）を選ぶ
   - 選択肢は「自分のみ」「（ドメイン）内の全員」「Google アカウントを持つ全員」「全員」などです（アカウントの種類により表示が変わります）
   - ⚠ **メールアドレスの取得に影響します**：「自分として実行」の場合、利用者のメールアドレスが取れるのは、所有者と**同じ Workspace ドメイン**の人だけです。
     「Google アカウントを持つ全員」「全員」にしても、社外や個人 Gmail の人は「ログインユーザーを確認できません」になります（打刻はされません）
8. **デプロイ** を押す（初回は「アクセスを承認」→ 許可）
9. 表示された **ウェブアプリの URL（末尾が `/exec`）** をコピーして開く → スタッフ画面が出れば完了
10. このURLをスタッフに共有します（スマホはホーム画面に追加すると便利です）

**コードを直したとき**：`npm run push` だけでは `/exec` の画面は変わりません。
**デプロイ → デプロイを管理 → 鉛筆（編集）→ バージョン：新バージョン → デプロイ** で更新してください（URLは変わりません）。
