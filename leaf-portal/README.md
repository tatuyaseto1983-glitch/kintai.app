# 株式会社リーフ 社内ポータル 勤怠管理（GASバックエンド）

Google スプレッドシートをデータベースにして、Google Apps Script（GAS）で勤怠を処理するバックエンドです。
今回は **GAS とシート構造のみ**です。スタッフ画面・管理者画面（HTML）は次の段階で作ります。

> このフォルダは、リポジトリ直下の `gas/`（ID・パスワード方式の別の勤怠アプリ）とは**別物**です。
> 混ぜずに、**新しいスプレッドシート**に入れてください。

---

## B. 最初にやる作業

1. Google ドライブで **新しいスプレッドシート** を作成（名前の例：「リーフ 勤怠データ」）
2. メニューの **拡張機能 → Apps Script** を開く
3. 最初からある `コード.gs` を開き、中身を消して **`Config.gs` の中身を貼り付け**、
   左の一覧でファイル名の「︙」→「名前を変更」で `Config` にする
4. 左の「ファイル」の **＋ → スクリプト** で、残りの `.gs` ファイルを1つずつ作って貼り付ける
   （名前は `Utils`、`SheetService` … のように `.gs` を除いた名前。**作る順番は自由**です）
5. すべて貼り付けたら **💾 保存**（Ctrl + S）
6. 上の関数の選択で **`setupSystem`** を選んで **▷ 実行**
7. 「承認が必要です」→ **権限を確認** → ご自身のアカウント →
   「このアプリは Google で確認されていません」と出たら **詳細** → **（プロジェクト名）に移動** → **許可**
8. 下の「実行ログ」に **【セットアップ結果】** が出れば成功
9. スプレッドシートに戻り、次の7シートができているか確認
   `スタッフマスタ / 勤怠記録 / 中断履歴 / 打刻修正申請 / 残業申請 / 日報 / 設定`
10. スプレッドシートを再読み込みすると、上のメニューに **「勤怠システム」** が出ます

- `setupSystem()` は **何回実行しても安全**です。既存のシート・データ・設定値は消しません。
  足りないシート、足りない見出し（右端に追加）、足りない設定項目だけを追加します。
- 最初からある「シート1」は削除しません。不要なら手で削除してください。
- 任意：Apps Script の ⚙「プロジェクトの設定」→ タイムゾーンを「(GMT+09:00) 日本標準時」に。
  （コードは日本時間を直接指定しているので、変更しなくても動きます）

## F. 【重要】Webアプリ公開時のメールアドレス取得の注意（`Session.getActiveUser().getEmail()`）

このシステムは「Googleアカウントのメールアドレス」でスタッフを判定します。
**Webアプリとして公開したとき、メールアドレスが取れない場合があります。**

| 公開の設定 | メールアドレス | 問題点 |
|---|---|---|
| 次のユーザーとして実行：**自分** | 利用者とスクリプトの所有者が **同じ Google Workspace（会社ドメイン）** のときだけ取れる。個人の Gmail 同士では **空になる** | Gmail 運用だと全員「メールアドレスを取得できませんでした」になる |
| 次のユーザーとして実行：**ウェブアプリにアクセスしているユーザー** | 取れる | スタッフ全員にスプレッドシートの編集権限が必要 → **シートを直接書き換えられてしまい、「申請→承認」の意味がなくなる** |

- エディタから実行する場合（今回のテスト）は、ご自身のアドレスが取れるので問題ありません。
- `Session.getEffectiveUser()` は「実行している人＝所有者」を返すため、**利用者の判定には使えません**（使っていません）。
- **画面を作る前に決める必要があります**：
  - 第一候補：会社の Google Workspace アカウント（@会社ドメイン）で運用し、「自分として実行」＋「アクセス：組織内のユーザー」で公開
  - 第二候補：個人 Gmail のままなら、HTML 側で Google ログイン（Google Identity Services）を行い、GAS 側でトークンを検証してメールアドレスを確認する方式に変更
  - おすすめしない：「アクセスしているユーザーとして実行」＋全員にシートの編集権限

## G. データの保存形式と、シートを直接直すときの注意

- 日付・時刻・時間は **文字列（書式なしテキスト）** で保存しています（例：`2026-09-29`、`09:30`、`08:10`、`138:00`）。
  「09:30」が勝手に別の値に変わるのを防ぐためです。手で入力するときも同じ形で入力してください。
- 列は **見出し名** で探しているので、列の並べ替えや右側への独自の列の追加をしても動きます。**見出し名は変えないでください**。
- シート上で出勤・退勤・中断履歴・残業申請のステータスを直接直したら、
  メニュー **勤怠システム → 今月の勤怠を再計算（管理者）** で計算列（実働・社内超過・要確認など）を更新してください。
- 勤怠記録・申請の行は削除しないでください（修正は打刻修正申請で）。

## H. 勤怠ルール（実装内容）

- **実働時間** ＝ 退勤 − 出勤 − 自動休憩（1:00）− 中断合計（マイナスにはしない）
- **固定勤務**：09:30 より後の出勤は「遅刻」、18:30 より前の退勤は「早退」、18:30 以降は「社内超過時間」（1分単位）
  - 社内超過時間は**社内管理用の数字**で、法律上の時間外労働（1日8時間・週40時間超）の計算とは別です
  - 30分以上なら承認済みの事前残業申請が必要。なければ「要確認」。**打刻・実働は申請に合わせて削ったり丸めたりしません**
- **フレックス**：遅刻・早退・社内超過は判定しません。週 32:00・月 138:00 に対する実働・残り・超過を集計
- **週1日の完全休日**：出勤記録がない日を完全休日として数え、`getFlexSummary()`（本人）と `checkWeeklyRestDays()`（管理者・全員）で確認
- **日付をまたぐ勤務**（例：22:00〜翌1:00）：前日の記録に退勤できます
- **同時実行**：出勤・退勤・中断・再開・申請・承認は LockService で1件ずつ順番に処理

### 設定シートの項目

指示いただいた10項目に加えて、次の3項目を追加しています（初期値は指示どおりの動きになる値です）。

| 項目 | 初期値 | 意味 |
|---|---|---|
| 週_起算曜日 | 月 | 週の集計を何曜日から始めるか |
| 月_締め日 | 末日 | 「末日」または 1〜27（例：20＝21日〜翌月20日） |
| 自動休憩_適用開始 | 00:00 | 出勤〜退勤がこの時間を超えた日だけ自動休憩を引く（00:00＝常に引く） |

## I. 開発者向け（パソコンでの自動テスト）

Node.js 20 以上で、GAS をまねた環境の上で全ファイルを動かしてテストできます。

```bash
npm test   # test/leaf-portal.test.js（このフォルダのテスト）と既存アプリのテスト
```

GAS のまね（モック）は `dev/leaf-gas-mock.js` です。
